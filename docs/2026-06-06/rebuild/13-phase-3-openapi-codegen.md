# Phase 3: OpenAPI Codegen Pipeline

**版本**: 1.0  
**日期**: 2026-06-06  
**范围**: backend-next 仅  
**基于**: Phase 2 Auth 迁移 (12-phase-2-auth-migration.md)

---

## 1. 目标

建立 OpenAPI codegen 流程，让 `backend-next/openapi/openapi-draft.yaml` 成为 Go API 类型和接口的来源。

**不是**：
- ❌ 搬 company 业务
- ❌ 重写 auth
- ❌ 接 PostgreSQL
- ❌ 改前端

**核心验收**：
1. OpenAPI draft 可以被 oapi-codegen 校验并生成 Go 代码
2. 生成代码在 `internal/generated/openapi/` 目录
3. 现有 hand-written auth handler 继续工作
4. Phase 2 测试全部通过
5. 有生成脚本（shell + PowerShell）

## 3. 范围内

- 新增 oapi-codegen 配置（`openapi/oapi-codegen.yaml`）
- 新增生成脚本（`scripts/generate-openapi.sh` + `.ps1`）

## 5. 生成代码规则

- 目录：`backend-next/internal/generated/openapi/`
- 禁止手改 generated 文件
- 文件头部标记：`// Code generated by oapi-codegen; DO NOT EDIT.`
- 业务代码只能依赖生成的 DTO 或 interface，不依赖实现细节
- 如果生成代码太大，应调整 oapi-codegen 配置或拆分 OpenAPI spec

---

## 6. OpenAPI 范围

第一批端点：

```yaml
GET  /healthz
GET  /readyz
POST /api/register
POST /api/login
GET  /api/v2/players/me/companies/   # 只写 contract，不需要实现
```

Auth DTO 必须包含：

```yaml
RegisterRequest
RegisterResponse
LoginRequest
LoginResponse
CompanySummaryDTO
ErrorResponse
ResponseMeta
```

## 9. 回滚方案

如果 codegen 失败：
1. 删除 `internal/generated/openapi/`
2. 删除 oapi-codegen 配置
3. 保留 hand-written auth handler
4. 回退 `openapi-draft.yaml` 到 Phase 2 状态
5. `go test ./...` 确认通过
6. 手动验证 `/api/register`、`/api/login`、`/healthz`
