## 5. Economic Formula Audit: "极简建筑产量版" Compliance

### 5.1 Building Production (Core)

**Spec v1.3.1/v1.3.2 requires:**
```
OutputPerHour_Lv1  = BuildingBaseOutputPerHour_Lv1 * (1 + FinalProductionSpeedBonus)
OutputPerHour_Level = OutputPerHour_Lv1 * BuildingLevel
```

**Current code (`formula/production.go`):**
```go
func BaseProductionRate(producedPerHourRaw, salaryModifier float64, salaryLevel int) float64 {
    sMid := SalaryMid[salaryLevel]  // {0:655, 1:700, 2:745}
    return producedPerHourRaw * math.Pow(AverageSalary/sMid, salaryModifier)
}

func ProducedPerHour(size int, baseRate, salaryPercent float64, robotCount int,
    isAccumulator bool, speedModifierPct float64, qualityPct float64, isMining bool) float64 {
    adjusted := baseRate
    if isMining { adjusted *= qualityPct / 100.0 }
    adjusted *= (speedModifierPct / 100.0) + 1.0
    effectiveSalary := salaryPercent
    if isAccumulator { effectiveSalary += RobotBonus * float64(robotCount) }
    den := 1.0 - effectiveSalary/100.0
    if den <= 0.01 { den = 0.01 }
    return float64(size) * adjusted / den
}
```

**Gap:**
- Still has `SalaryMid`, `AverageSalary`, `SalaryMid[0..2]` — legacy salary/worker variables the spec says to delete
- Still has `robotCount`, `isAccumulator`, `isMining` — concepts removed in spec
- No `BuildingBaseOutputPerHour_Lv1` concept in formula — `producedPerHourRaw` comes from resource data, not from building stats
- No clean `(1 + speedBonus)` multiplicative factor — speed modifier is `(speedModifierPct/100 + 1)` which is close but mixed with salary division
- The `ProducedPerHour` function uses `size` (building level) divided by `(1 - salaryPercent/100)` which is a tax-like formula, not linear level multiplier
- `calcProductionDuration` reads `buildingLevelsNeededPerUnitPerHour` from economy model JSON — bypasses the simple formula entirely

### 5.2 Cost Indices

**Spec requires:** `LaborCostIndex`, `MaterialCostIndex`, `EnergyCostIndex` as global tunable parameters in `game.json`.

**Current code:** No cost index fields in `game.json`. The config has `BotOrderBase`, `ProductionMod`, `AdminOverheadBase`, etc. but no cost indices.

### 5.3 Saturation Price Control

**Spec requires:**
```
SaturationPriceMultiplier = CLAMP(0.70, 1.10, 1 - MAX(0, MarketSaturationGroup - 1) * SaturationK)
EffectivePrice = BasePrice * SaturationPriceMultiplier * EventPriceMultiplier
```
with commodity groups: `Grain`, `Dairy`, `Processed`, `Bakery`, `GeneralMarket`, `CafeDessert`, `StreetFood`, `RestaurantMeal`, `Finance`.

**Current code:**
- No `SaturationPriceMultiplier` formula exists anywhere
- No commodity groups defined — groups from spec (Grain, Dairy, etc.) are not present
- `MarketPressure` map `{resourceID → float}` accumulates per-resource pressure via `+ 0.02 * bought` on each trade, capped at 1.0 — this is a rough proxy, not saturation-based
- `CheckMarketLock` uses side ratios (sell qty : buy qty vs yesterday volume) and price thresholds to trigger market locks / national team — this is a circuit breaker, not a saturation price curve

### 5.4 Bot / Market Maker

**Spec requires:**
```
BotBidPrice = FairPrice * (1 - BotSpread)
BotAskPrice = FairPrice * (1 + BotSpread)
```
with liquidity limits and no infinite arbitrage.

**Current code** (`market_competition.go:RunBotMarketCycle`):
```go
buy.Price = math.Round(buyBase * cycleVol * (1 - spread) * 100) / 100
sell.Price = math.Round(basePrice * cycleVol * (1 + spread) * 100) / 100
```
- ✅ Spread formula matches spec
- ✅ `cycleVol` adds sinusoidal amplitude (BotCycleAmplitude=0.06) — hourly rhythm
- ✅ Bot inventory replenishment is bounded (`BotOrderQty*80` ceiling, `BotOrderQty*25` floor)
- ✅ Bot money replenishment at `BotMoney/2` threshold
- ✅ MaxBotOrders cap (600) prevents order book flooding
- ✅ `replaceBotOrders` reduces bot presence proportionally to player market entry (anti-arbitrage)
- ⚠️ `FairPrice` is computed via `ComputeChainPrice()` (a 3-tier profit-split model) rather than spec's simple `BasePrice × SaturationPriceMultiplier` — because saturation multiplier doesn't exist yet
- ⚠️ Bot cycle replaces ALL bot orders every hour (removes old, creates new) rather than delta-adjusting

### 5.5 Executive + Reputation

**Spec requires:** additive: `ExecutiveBonus + GlobalReputationBonus` (no multiplicative explosion).

**Current code:** Executive bonuses are stubs — neither implemented nor tested. No production/sales bonus application in service layer.

### 5.6 Bond 50x Coefficient

**Current code** (`formula/bonds.go`):
```go
func DailyBondInterest(amount int, interestRatePct float64) float64 {
    return math.Floor(float64(amount) * 50.0 * interestRatePct)
}
```

At 1.2% interest rate: `5000 * 50 * 0.012 = 3000/day` on a 5000 face-value bond = **60% daily return**. This is clearly imbalanced.

**`PeriodBondInterest`** uses `BondFaceValue` (5000) instead:
```go
func PeriodBondInterest(amount int, interestRatePct float64) float64 {
    return math.Floor(float64(amount)*BondFaceValue*interestRatePct) / 100.0
}
```
- `5000 * 5000 * 0.012 / 100 = 3000` — same result, likely double-counts face value.
