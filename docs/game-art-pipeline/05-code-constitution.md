# 反屎山代码宪法

## 第一条：单一真相

游戏状态只能有一个真相来源。
正式阶段以 Go API 为准，不允许 Node demo API 和 Go API 同时混用成两套业务逻辑。

## 第二条：配置优先

建筑、资源、等级、动画、占地、产出和素材路径必须配置化。
不允许在 UI 组件里写大量建筑专属 if/else。

## 第三条：渲染和业务分离

Phaser 只负责地图渲染和交互反馈。
React 只负责外层 UI。
后端请求只能在 API client/action 层发生。

## 第四条：素材注册制

所有素材必须进入 asset registry。
不允许组件直接散落 import 一堆具体建筑图片。

## 第五条：命名不可随意

素材文件必须符合命名规范。
任何 `new.png`、`test2.png`、`final_final.png` 都不允许进入正式目录。

## 第六条：先文档后扩展

新增产业链前，必须先写产业链设计文档。
新增建筑前，必须先定义 building_id、等级、状态和素材需求。

## 第七条：小步验证

第一阶段只做一条产业链。
不要为了“看起来丰富”一次塞几十个建筑和资源。

## 第八条：API 隔离

组件不得直接依赖 Go API 的原始返回结构。
必须通过 adapter 转换成前端稳定模型。

## 第九条：地图不是表格

地图应该是可读、可交互、有状态的经营空间。
不要把中心区域做成股票表、Excel 表、六宫格卡片或静态海报。

## 第十条：素材实验和正式资产分离

AI 生成原图、透明图、spritesheet、最终接入资产必须分目录。
实验素材不得直接污染源码资产目录。
