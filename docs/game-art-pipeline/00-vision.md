# 游戏美术与开发规划书

## 定位

本项目不是字面意义上的种田游戏，也不是股票交易终端，而是“产业链收菜经营”游戏。
玩家经营一张不断扩展的产业地图，通过建造、等待、收取、加工、出售、交付订单和升级，形成稳定的经营循环。

## 核心体验

玩家看到的核心画面应该是一张有生命感的经营地图，而不是六个呆板建筑卡片。
地图上应该有道路、建筑节点、扩展地块、生产状态、可收取提示、订单入口和市场价格反馈。

## 第一阶段产业链

第一阶段只选择一条产业链，避免一开始铺太多内容导致设计和代码都失控。

推荐产业链：

`小麦 -> 面粉 -> 面包 -> 简餐`

对应建筑：

- `grain_plot`：粮食产出节点
- `mill_house`：磨坊/加工节点
- `bakery_shop`：面包坊/二级加工节点
- `meal_kiosk`：简餐售卖节点

每个建筑先做 3 个等级：

- `lv1`：手工、简陋、低产
- `lv2`：标准化、稳定、效率提升
- `lv3`：自动化、高产、有明显机械感

## 地图视觉方向

地图是暖色 2.5D 经营地图，不要真实农场照片感。
建筑应该有清晰轮廓、轻微描边、可读性强，能在中等尺寸下辨认等级。

地图中应该出现：

- 可放置地块
- 道路连接
- 建筑生产状态环
- 可收取发光提示
- 地块扩展边界
- 市场/合同/研究等功能入口

## UI 方向

底部不再显示库存条，而是显示最新市场价格。
库存和仓库信息应该放到仓库页或右侧详情里。

底部价格条示例：

- Wheat `$4.20` `+2.1%`
- Flour `$7.80` `-0.6%`
- Bread `$11.50` `+1.2%`
- Meal `$28.40` `-1.5%`

## 本轮职责边界

本轮只产出文档、提示词、素材和素材规范。
不修改 React、Phaser、Go 或 Node 业务代码。
