# Arch-QA: Architecture Quality Assurance

Run multi-tool analysis on the project and produce a standardized Markdown report comparing Backend-Next vs Backend (Old).

## Prerequisites

Tools must be installed globally:
```bash
# Go tools
go install github.com/golangci/golangci-lint/cmd/golangci-lint@v1.63.4
go install github.com/roblaszczak/go-cleanarch@latest

# Node tools
npm install -g eff-u-code          # fuck-u-code
npm install -g madge                # circular deps
npm install -g dependency-cruiser   # module boundary rules
npm install -g jscpd                # copy-paste detection
```

## Usage

```bash
# Quick — generate full report (takes ~30s)
node scripts/arch-qa-report.mjs

# Or step by step:
# 1. Run all tools
bash scripts/run-arch-qa.sh

# 2. Generate report from cached results
node scripts/arch-qa-report.mjs
```

## Tools & What They Check

| Tool | Target | Checks | Output |
|------|--------|--------|--------|
| `fuck-u-code` | next + old | Code cleanliness (complexity, size, naming, comments, structure) | Score 0-100 per file |
| `golangci-lint` | next + old | Lint errors (errcheck, staticcheck, unused, gosimple, ineffassign) | Issues per file |
| `go-cleanarch` | next + old | Dependency direction (domain must not import handler/service/storage) | Pass/Fail |
| `madge` | frontend | Circular imports in TypeScript | Circular dep list |
| `dependency-cruiser` | frontend | Architecture boundary rules (e.g. features don't import each other) | Violation list |
| `jscpd` | next + old + frontend | Copy-paste detection | Clone locations |

## Report Sections

The generated `arch-qa-report.md` contains:

1. **Overall Score** — fuck-u-code scores, averages, distribution
2. **Project Size** — file count, LOC, package count, depth
3. **Architecture Comparison** — directory tree, package organization, domain separation
4. **Code Quality (golangci-lint)** — issues by linter, worst files side-by-side
5. **Clean Architecture** — go-cleanarch result
6. **Frontend** — circular deps, module boundaries
7. **Verdict** — structured comparison table with winner per dimension

## Interpreting Results

- **Average file score** is more meaningful than overall score: overall is pulled down by file count
- **Package depth** and **domain separation** matter more than per-file lint metrics
- Old backend scores well on per-file metrics because it spreads logic across many small files (same complexity, worse organization)
- Next is architecturally cleaner (domain-bounded packages, central routing, clear layering) even when per-file scores are slightly lower

## Automation

For CI, run:
```bash
node scripts/arch-qa-report.mjs
```

The script reads cached JSON outputs from:
- `golangci-next.json`, `golangci-old.json` (generated by golangci-lint)
- It runs `fuck-u-code`, `madge` live (fast, <1s each)

All results in `arch-qa-report.md`.
